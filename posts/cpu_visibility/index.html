CPU的可见性

2025年7月9日cpu

从软件开发视角理解 CPU 缓存一致性与 MESI 协议。

声明

  • 本文内容提到的CPU仅指市面上主流的CPU，并非所有的CPU都是这种结构与处理方式
  • 本文内容对CPU的结构仅提及软件开发所需要了解的部分
  • 本文内容提供给软件开发扩展底层原理

文章中用到的名词对应解释

名词 解释
缓冲区（WriteBuffer） 用来帮助 cpu 执行需要写入到 L1、L2、L3 高速缓存的写入操作
L1、L2、L3（高速缓存） cpu 自身硬件提供的高速缓存，用来提高 cpu 访问缓存的效率
缓存（Cache） 通常情况下用于短暂存储数据，当不需要使用时就把数据清理掉
缓存行（Cache Line） 缓存被分成很多相同大小的块，这些块被称为缓存行。常用 cpu 高速缓存的缓存行大小为 64 字节
缓存空间（Cache Space） 与缓存是同一性质，不同称呼罢了
独享（Exclusive） 只有自己在用
共享（Share） 大家一起使用
内存（Memory） 内存条中用来在系统运行时存数据的空间
主内存（Main Memory） 所有内存条中的空间合并到一起称为主内存
DMA（Cache-Coherent DMA） 实现外设与内存直接进行数据传输‌，从而‌降低CPU的占用率并提升数据传输效率
总线嗅探（Bus Snooping） 每个CPU核心会持续监听总线上的所有事务
总线广播（Bus Broadcasting） 当某个CPU核心需要修改共享数据时，通过总线向所有其他核心发送通知

CPU与主内存？

CPU组成

CPU中有 寄存器、写缓冲区、L1、L2、L3 等

写缓冲区

CPU厂商为了进一步提高CPU的写入效率在 L1 与 CPU核心 之间加入了 写缓冲区

当CPU需要对 L1、L2、L3 的 缓存行 进行写操作时，部分写操作会交由 写缓冲区 执行写操作到 L1、L2、L3

高速缓存

由于CPU的执行效率远胜于主存执行读写的操作效率，CPU厂商为了提高CPU的读写性能在CPU中加入了高速缓存，高速缓存介于CPU与主存之间，用于提高CPU的读写性能

L1 到 L3 数字越小离 CPU 越近，执行效率越高，缓存空间 越小

L1 和 L2 缓存是单个 CPU核心 独享的 缓存空间

L3 是所有 CPU核心 共享的 缓存空间

高速缓存 L1、L2、L3 并非是一个完整的缓存空间，而是被分成大小相同的 缓存行 ，目前市面上主流的 缓存行 大小为 64 字节

主内存

所有物理内存条的 内存 合并到一起统称为 主内存，简称 主存

CPU与主内存大致结构示意

  • CPU
    • CPU 核心（多个）
      • 写缓冲区（WriteBuffer）
      • L1（高速缓存）
      • L2（高速缓存）
    • CPU 核心 2
      • 写缓冲区（WriteBuffer）
      • L1（高速缓存）
      • L2（高速缓存）
    • L3（高速缓存）
  • 主内存（Main Memory）

缓存不一致问题？

CPU单核情况下使用**DMA（直接内存访问）**会导致的内存与缓存不一致

  1. 选择带缓存一致性的DMA（Cache-Coherent DMA），自动维护缓存与内存一致性
  2. 选择在DMA操作前后，调用 flush_cache() 或 invalidate_cache() 等指令手动同步

CPU工作模式

CPU在单核情况下通常是不会发生缓存不一致问题的，所以这里介绍的是CPU多核模式

cpu 创建变量时会依次写入 L1、L2、L3、主内存。 cpu 获取变量时会依次访问 L1、L2、L3、主内存，拿到变量时尝试依次写入到 L3、L2、L1 中

缓存不一致问题是怎么发生的？

当我们在代码中创建变量 a = 1 时，CPU 将变量写入到主存中，这时 cpu 自身已经缓存了一份变量 a 的值

当另外一个线程通过 cpu 2 获取变量 a 的值时，它会和 cpu 1 一样的工作模式，从 L3 中获取变量 a 并尝试依次写入 L2、L1

在上述操作中 cpu 1、cpu 2 均将变量 a 的值缓存到了自身独享的高速缓存中时，某个线程通过 cpu 1 修改变量 a = 2，这时 cpu 2 缓存的变量 a 还是原来的 1，当有新线程通过 cpu 2 获取变量 a 时拿到的数据就是 脏数据（因为变量 a 最新的值还在 cpu 1 的高速缓存中）

MESI协议？

  • M（Modified）缓存行被当前核心修改，与主内存不一致

    当前核心修改缓存行时通过总线广播通知其他核心缓存行标记为 I 失效 当前核心访问标记 M 缓存行时，直接进行操作 其他核心访问 M 缓存行时，会等当前核心将 M 缓存行同步主存，然后获取并将当前缓存行与其他缓存行都标记为 S 共享 当前核心高速缓存空间不足时会将标记为 M 的缓存行同步主存

  • E（Exclusive）缓存行仅当前核心持有，与主内存一致

    核心访问标记 E 的缓存行时无需任何处理 当其他核心缓存行与主存不一致时(标记为 I 失效)，当前缓存行保持 E 独享

  • S（Shared）缓存行被多个核心持有，与主内存一致

    核心访问标记 S 缓存行时无需任何处理

  • I（Invalid）缓存行无效，需要从主内存中重新获取

    核心访问标记 I 的缓存行时，会等 M 缓存行的核心同步主存，然后通过主存更新当前缓存行 S 共享

总线嗅探与总线广播？

总线嗅探（Bus Snooping）

每个CPU核心会持续监听总线上的所有事务（如读/写请求、无效化命令等），并根据监听到的消息更新本地缓存行的状态或数据。

  • 检测其他核心对共享数据 S 的修改或访问请求
  • 根据MESI协议规则触发本地缓存行的状态流转

总线广播（Bus Broadcasting）

当某个CPU核心需要修改共享数据时，通过总线向所有其他核心发送通知（如无效化请求），要求它们更新或丢弃旧副本。

  • 声明对数据的独占访问权（当前核心修改共享数据将缓存行状态从 S 共享 变更为 M 修改）
  • 强制其他核心放弃旧副本（缓存行状态变更为 I 失效），确保修改的原子性

MESI协议是怎么解决缓存不一致问题的？

文字形式有点不便于理解，后续会贴图

这里为了便于理解，操作的高速缓存为L1

单核操作

初始数据

主存
	a = 1
cpu1
	L1
		缓存行
			a = 1

cpu1 从主存中获取变量 a = 1 并写入到缓存行，这时cpu1 的缓存行与主存一致，所以缓存行状态为 E 独享

主存
	a = 1
cpu1
	L1
		缓存行（E）
			a = 1

cpu1 执行修改操作 a = 2，这时cpu1的缓存行变量 a = 2，与主存不一致，所以缓存行状态变更为 M 修改

主存
	a = 1
cpu1
	L1
		缓存行（M）
			a = 2

注意：缓存的状态为 M 时，并不会主动的更新主存！

  1. 当cpu 的高速缓存空间不足时会将状态为 M 修改的缓存行同步至主存
  2. 当其他 cpu 核心需要访问状态为 M 的缓存行中的变量时，会主动同步至主存

多核操作

初始数据

主存
	a = 1

cpu1 从主存中获取变量 a = 1，这时cpu1 缓存行数据与主存一致，所以缓存行状态为 E 独享

主存
	a = 1
cpu1
	L1
		缓存行（E）
			a = 1

cpu2获取变量 a，通过总线广播通知其他持有该变量的缓存行状态变更为 S（如果获取的变量在其他核心有没同步主存的情况会通知对应核心立即同步主存）

主存
	a = 1
cpu1
	L1
		缓存行（S）
			a = 1
cpu2
	L1
		缓存行（S）
			a = 1

cpu1 执行修改操作 a = 4，在修改前先通过总线广播通知其他核心将变量 a 所在的缓存行标记为失效 I，这时cpu1的缓存行数据 a = 4，这时与主存不一致，所以缓存行状态为 M

主存
	a = 1
cpu1
	L1
		缓存行（M）
			a = 4
cpu2
	L1
		缓存行（I）
			a = 1

cpu2 获取或操作变量 a 时（如果获取的变量在其他核心有没同步主存的情况会通知对应核心立即同步主存），发现缓存行失效，等待其他核心同步主存后获取变量 a 并更新对应缓存行，这时 cpu1、cpu2 都与主存一致，所以缓存行状态为 S

主存
	a = 4
cpu1
	L1
		缓存行（S）
			a = 4
cpu2
	L1
		缓存行（S）
			a = 4

Write Buffer 写缓冲区？

在上述内容中我们了解了写缓冲区是CPU厂商为了进一步提高写入效率在L1与CPU内核之间用于执行部分写入操作的空间

写缓冲区的工作模式

当CPU内核需要执行写操作时，部分写操作会交给写缓冲区执行，由写缓冲区后续执行写操作到缓存行。

写缓冲区的缓存不一致问题？

由于写操作直接交给写缓冲区没有操作缓存行，所以不会触发MESI协议将其他CPU内核的缓存行标记为 I 失效，这时其他CPU内核获取缓存行数据会再次出现缓存不一致问题！

失效广播

CPU内核将写操作交给写缓冲区时会发送失效广播通知其他CPU内核将对应操作变量的缓存行标记为 I 失效，以此来保证触发MESI协议解决缓存一致性问题
